# RollPeriod By MARIN

RollPeriod is a Flutter mobile application for collecting vessel roll and
pitch data, calculating roll periods with FFT processing, storing measurements,
and displaying prediction and navigation charts.

## Requirements

- Flutter SDK 3.7.2 or newer, with Dart included
- Android Studio and an Android SDK for Windows/Android development
- Xcode and CocoaPods for macOS/iOS development
- Git
- A physical phone or an Android/iOS simulator

Check the local installation with:

```bash
flutter --version
flutter doctor
```

Resolve the issues reported by `flutter doctor` before running the application.

## Install the Project

Clone the repository, enter its directory, and install the Dart/Flutter
packages:

```bash
git clone https://github.com/Teiiva/RollPeriodApp.git
cd RollPeriodApp
flutter pub get
```

Confirm that Flutter can see a target device:

```bash
flutter devices
```

Run the app from the project root:

```bash
flutter run
```

To select a specific device, use its identifier from `flutter devices`:

```bash
flutter run -d <device-id>
```

## Android Virtual Phone on Windows

1. Install [Android Studio](https://developer.android.com/studio) and let the
	setup wizard install the Android SDK, Android SDK Platform-Tools, and an
	Android Emulator.
2. Open Android Studio and choose **More Actions > SDK Manager**. In **SDK
	Platforms**, install a recent Android platform. In **SDK Tools**, ensure
	**Android SDK Build-Tools**, **Android SDK Command-line Tools**, and
	**Android Emulator** are installed.
3. Open **More Actions > Virtual Device Manager**. Select **Create device** and
	choose a phone profile, such as Pixel.
4. Select an x86_64 or arm64 system image, download it if necessary, and finish
	creating the device. A recent stable API level is recommended.
5. Start the virtual phone with the play button in Device Manager.
6. From PowerShell in the project directory, verify that it is available:

	```powershell
	flutter doctor
	flutter devices
	flutter pub get
	flutter run
	```

If Flutter cannot find the Android SDK, set the SDK path in Android Studio and
run `flutter config --android-sdk <SDK_PATH>`. On Windows, enabling hardware
virtualization in UEFI/BIOS and using Windows Hypervisor Platform may improve
emulator performance.

> **The Android emulator can run the interface, but simulated sensor values may
> not behave like a physical accelerometer. Use a real Android phone when testing
> sensor collection and motion-dependent results.**

## iPhone Simulator on macOS

1. Install Xcode from the Mac App Store.
2. Open Xcode once and accept the license. Install the requested command-line
	tools when prompted.
3. In Xcode, open **Settings > Components** (or **Platforms**, depending on
	the Xcode version) and install an iOS Simulator runtime.
4. Start a simulator from **Xcode > Open Developer Tool > Simulator**, or from
	the terminal with:

	```bash
	open -a Simulator
	```

5. In the project directory, install iOS dependencies and run the app:

	```bash
	flutter doctor
	flutter pub get
	cd ios
	pod install
	cd ..
	flutter devices
	flutter run -d <ios-simulator-id>
	```

You can also open `ios/Runner.xcworkspace` in Xcode when you need to change
iOS signing, capabilities, deployment settings, or native iOS configuration.
Use a physical iPhone for reliable accelerometer testing because Simulator
does not reproduce every real-device motion sensor behavior.

## Project Structure

### Application code

- `lib/main.dart`: Application entry point. Initializes Flutter, locks the app
  to portrait orientation, registers Provider state, and creates the root app.
- `lib/menu.dart`: Main menu and navigation entry screen.
- `lib/sensor_page.dart`: Accelerometer collection, roll/pitch charts, data
  import/export, tutorials, and measurement controls.
- `lib/prediction.dart`: Roll-period prediction chart and saved coefficient
  settings.
- `lib/fft_processor.dart`: FFT-related signal processing used by sensor data.
- `lib/shared_data.dart`: Shared Provider state for the selected vessel and
  loading condition.
- `lib/storage_manager.dart`: Manage data saving and loadinf between app sessions.
  `shared_preferences`.
- `lib/datas.dart`: Vessel and Voyage data and associated charts.
- `lib/tutorial.dart`: In-app tutorial for `sensor_page.dart`.
- `lib/android_widget_provider.dart`: Android widget/provider integration.

### Models and widgets

- `lib/models/vessel_profile.dart`: Vessel profile data.
- `lib/models/loading_condition.dart`: Loading (also named voyage) profile data
- `lib/models/saved_measurement.dart`: Structure for saved measurements.
- `lib/widgets/custom_app_bar.dart`: Shared application bar which qllows you to choose the vessel

### Assets and platform folders

- `assets/fonts/`: Bundled font files. Registered in `pubspec.yaml`.
- `assets/images/`: Images used by the application.
- `assets/icons/`: Roll and pitch icons.
- `assets/sounds/`: Alarm sounds.
- `pubspec.yaml`: Project metadata, SDK constraints, dependencies, assets, and
  fonts.
- `android/`: Android application, manifest, Gradle configuration, and native
  permissions.
- `ios/`: iOS application, CocoaPods configuration, signing, and native
  permissions.
- `test/`: Flutter and Dart tests, including `widget_test.dart`.

## How to Modify the Project

1. Create a branch for the change:

	```bash
	git checkout -b feature/my-change
	```

2. Make the smallest change in the relevant `lib/` file. Keep reusable data in
	`models/`, shared state in `shared_data.dart`, and repeated UI in
	`widgets/`.
3. If you add a package, update `pubspec.yaml` and run:

	```bash
	flutter pub get
	```

4. If you add an image, sound, or font, place it under `assets/` and register
	its path in the `flutter.assets` or `flutter.fonts` section of
	`pubspec.yaml`.
5. If you change Android or iOS permissions, update the corresponding native
	configuration in `android/` or `ios/` and test on the target platform.
6. Format, analyze, and test before committing:

	```bash
	dart format lib test
	flutter analyze
	flutter test
	```

7. Run the app on a simulator and, for sensor-related changes, on a physical
	device as well.

## Troubleshooting

- If packages or generated files are out of sync, run `flutter clean`, then
  `flutter pub get` and `flutter run`.
- If no device appears, start the Android emulator or iOS Simulator and run
  `flutter devices` again.
- If iOS packages fail, run `pod install` from `ios/` and ensure Xcode is the
  active developer directory.
- If sensors do not produce useful data in a simulator, test with a physical
  device.
